# Cosmopolitan Asset Register
1. `cd server && cp .env.example .env`; set `MONGODB_URI` and `APP_URL` to the public client URL. For local development, create a unique 48-byte secret directly in the git-ignored `.env` without printing it: `node -e "const fs=require('node:fs'),c=require('node:crypto'),p='.env';let s=fs.readFileSync(p,'utf8'),v=c.randomBytes(48).toString('base64url');s=/^JWT_SECRET=.*$/m.test(s)?s.replace(/^JWT_SECRET=.*$/m,'JWT_SECRET='+v):s+String.fromCharCode(10)+'JWT_SECRET='+v+String.fromCharCode(10);fs.writeFileSync(p,s)"`. For deployment, use the platform’s protected secret/environment-variable store and do not place secrets in source, shell arguments, build logs, or chat. API startup rejects known placeholders and secrets shorter than 32 characters. Rotating `JWT_SECRET` invalidates every existing login and password-reset token; update it consistently across API instances and have users sign in again. Set `CORS_ORIGINS` to a comma-separated allow-list of exact client origins if the deployed client is on a different origin; do not use `*`. Set `SEED_ADMIN_PASSWORD` and `SEED_OPERATOR_PASSWORD` in `.env` to distinct passwords of at least 12 characters when creating the initial accounts, then run `npm i && npm run seed && npm start`.
2. `cd client && npm i && npm run dev` (proxies /api to :4000)
The seed script creates `admin@cosmopolitan.local` (super admin) and `carcar@cosmopolitan.local` (Carcar operator) only when those accounts do not already exist. It never resets existing account passwords. Rotate any credentials that may have been used with an older deployment.
To apply the SOUTH/NORTH cluster setup to an existing database, run `cd server && npm run seed` again. It updates seeded branches and their assets, then removes the legacy Metro Cebu cluster when nothing still references it. If other branches or assets still reference Metro Cebu, reassign their branches to SOUTH or NORTH in **Administration → Branches** and rerun the seed.
To safely reset a legacy account, sign in as an authorized superadmin over HTTPS, open **Administration → Users**, choose **Edit** for the affected account, enter a new unique password, and save. This changes only that account’s password hash and preserves its other data. If the superadmin cannot sign in, use the configured email recovery flow or arrange a controlled, authenticated administrative reset in staging. The `server/create-user.js` utility also accepts account details as arguments and reads the password through a hidden interactive prompt; run it from a terminal, never pass passwords as command-line arguments or print them. New accounts created by this utility require at least 12 password characters. The legacy seed accounts potentially affected by the earlier shared-password seed are `admin@cosmopolitan.local` and `carcar@cosmopolitan.local`.
Password recovery requires SMTP settings in `server/.env` (`SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, and `SMTP_FROM`). Users verify the emailed six-digit code before choosing a new password. Codes expire after 10 minutes, can be requested once per minute, and allow five attempts; successful verification grants a single-use, 10-minute password-reset token. Configure a real email provider before enabling password recovery in production.
Register Asset accepts a quantity of 1–500 and creates one independently tracked record per physical item. Each record gets its own branch-prefixed inventory tag, QR token, condition, status, location, and history. Condition starts as `Good`; the entered serial number is assigned to the first record only, and cost is per item. Excel import also accepts a Quantity column (defaults to 1 for older templates) and generates consecutive individual inventory tags for each row. An import can create up to 500 records in one atomic operation. Quantity registration and Excel imports use MongoDB transactions, so the database must support transactions (for example, a replica set or MongoDB Atlas).
QR labels encode only each record's inventory tag, so mobile camera apps show the asset code instead of a website URL. The in-app scanner accepts both inventory tags and older QR URLs. The detail page still has its own link and persistent QR token. To update existing records and regenerate their QR images with inventory-tag-only codes, run `cd server && npm run migrate-qr-codes`, then download and print fresh labels.
